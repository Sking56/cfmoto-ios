# Architecture decisions

ADR-001 — Research before implementation. Context: the brief mandates staged protocol/platform/licensing research. Decision: initialize a minimal dependency-free SwiftUI skeleton and independent workstreams before protocol or capture implementation. Alternative: implement guessed protocol immediately. Consequences: no advertised mirroring capability until verification. Status: accepted.

ADR-002 — Deployment target. Context: brief targets iOS 27+. Decision: preserve 27.0 in the project; require matching SDK/runtime and record unavailable builds honestly. Alternative: silently lower the target. Consequences: contributors need suitable Xcode. Status: accepted pending SDK/device validation.

ADR-003 — License pending. Context: owner has not selected a license. Decision: keep an explicit placeholder and audit reference obligations before reuse. Alternative: choose an arbitrary license. Consequences: no redistribution grant is asserted. Status: pending owner decision for later distribution.

ADR-004 - Host-testable protocol core. Context: the original Mac toolchain was below the native target; it is now upgraded to Xcode 27. Decision: compile Foundation-only Pairing/EasyConnect sources as a dependency-free Swift package on macOS; retain iOS 27 in the app. Alternative: block protocol work on an SDK upgrade. Consequences: host XCTest and independent Python peer provide protocol evidence separately from native/device evidence; native skeleton build/analyze/launch now pass. Status: independently approved for Gate 1 at fde4c81; physical capture remains unverified.

ADR-005 - Callback topology and explicit synthetic identity. Context: the reviewed source uses phone listeners, dash-initiated callbacks and pulled raw video; Android identity/RSA acceptance on iPhone remains unresolved. Decision: classify all four callbacks explicitly, require complete negotiation evidence, and inject identity; any host-only synthetic identity is accepted solely by an explicitly synthetic peer. Alternative: guess hardware identity or treat wake/one socket as ready. Consequences: useful deterministic integration without a TFT authentication claim. Status: independently approved for the synthetic Gate 1 at fde4c81; hardware identity remains unresolved.
